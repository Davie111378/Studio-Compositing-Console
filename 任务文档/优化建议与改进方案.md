# Agent 能力优化建议与改进方案

> 基于 2026-09-12 全量测试结果制定。测试覆盖抠图 (P3M-10k + HM-1k)、绿幕背景合成、滤镜/特效、文本理解 (25 条 Planner 用例)。

## 一、问题清单

### 1.1 抠图 (T01_matting)

| 数据集 | avg SAD | 评级 | 根因 |
|---|---|---|---|
| P3M-10k | 2.77 | 优秀 | — |
| HM-1k | 402.26 | **严重失败** | BiRefNet 训练域与 HM 低分辨率/高压缩数据不匹配; alpha 输出在颈部/躯干出现大面积空洞 |

**问题**: BiRefNet 对 HM-1k 的真实视频帧截图人物, 身体区域被误判为背景, alpha 出现大面积黑色空洞。边缘发丝细节丢失, 二值化严重。

### 1.2 绿幕背景合成 (T02/T06)

| 测试项 | 结果 | 问题 |
|---|---|---|
| T06 greenscreen 模式 | alpha 检测正确 | 功能可用, 色度键 + despill 正常 |
| T02 green_key 模式 | 合成功能可用 | 缺少投影和光影匹配; 人物直接叠加, 空间层次不足 |

**问题**: greenscreen 模式的 alpha 和合成逻辑正确, 但 Planner 未能正确规划"绿幕实景照片保留实物"场景的完整链路 (缺少 T02 背景生成节点)。

### 1.3 滤镜/特效 (T07_enhance)

| mode | 功能可用 | 问题 |
|---|---|---|
| depth_blur | 是但**无效果** | `fx_library._exec` 无 `depth_blur` 分支, 落入 unknown 警告 |
| sharpen/grain/vignette/warm/cool/sticker/watermark_text | 全部正常 | — |

**问题**: `adapter.t07_enhance` 调用 `fx_auto.place(arr, "depth_blur")`, 但 `fx_library._exec` 的 if-elif 链没有 `depth_blur` 分支, 只有 `fx_tool._DISPATCH` 有。调用路径错误导致景深虚化不生效。

### 1.4 文本理解 (Planner)

通过率: **21/25 (84%)**

| 用例 | 指令 | 失败原因 |
|---|---|---|
| G3 | "绿幕演播室照片只换掉绿幕部分, 桌子和话筒保留" | 缺少 T02 背景生成节点, 只走了 T06 |
| G4 | "绿幕区域替换成综艺背景, 保留所有实物" | 误判为纯 green_key, 未识别"保留实物"信号 |
| M4 | "帮我写一首诗" | 未拒绝域外请求, 错误映射到 T07 |
| M5 | "这把椅子换颜色" | fallback 误走 T08 导出 |

## 二、改进方案

### 2.1 抠图后处理修复 (adapter.py)

在 `t01_matting` 的 BiRefNet 输出后增加:
- **形态学闭运算**: 用 9x9 椭圆核填充 alpha 内部小空洞
- **连通域分析**: 保留最大前景连通域, 删除碎噪; 对主体内部空洞做 floodFill
- **人体躯干连通性保护**: 检测 alpha 中从头部到躯干的断裂, 用形态学桥接

### 2.2 depth_blur 调用路径修复 (fx_library.py)

在 `fx_library._exec` 的 if-elif 链中增加 `depth_blur` 分支:
- 调用 `fx_tool.depth_blur` 或直接内联实现
- 自动生成中心区域 mask (用现有 `AUTO_PRESET` 的 center 布局)
- 用 `keep_region=True` 保持中心清晰, 外围虚化

### 2.3 Planner 文本理解修复 (prompt.py + planner.py)

**prompt.py RULES 增补**:
- 规则 4a: "保留桌台/话筒/实物" + "换绿幕" → 必须先 T02 生成背景 + T06 mode=greenscreen
- 规则 13 (abstain): 非图像编辑指令 (写诗/聊天/问天气) → `{"intent":"abstain","nodes":[],"outputs":[]}`
- 规则 14 (能力边界): 物体级颜色编辑/文字内容修改 → abstain
- 增加 2 条 few-shot: greenscreen 保留实物场景 + abstain 场景

**planner.py fallback 增补**:
- 在 fallback_plan 开头增加 abstain 检测: 非图像编辑关键词 → 返回 abstain DAG
- 修复 greenscreen fallback: 确保 T02 在 T06 之前

### 2.4 SFT 训练数据补充

在 `agent_training/build_sft_data.py` 中增加:
- G3/G4 类: 绿幕实景保留实物 → T02 + T06(greenscreen) 双节点
- M4 类: 域外请求 → abstain
- M5 类: 物体级编辑 → abstain
- 目标: 文本理解通过率从 84% 提升到 >95%

## 五、后续训练建议

### 5.1 HM-1k 域适配 (已验证: 当前架构不可行)

BiRefNet 对 HM 数据的 SAD=402 (P3M 仅 2.77), 差距 145 倍。根因是域偏移:
- HM 图像: 低分辨率 (800x600), 高 JPEG 压缩, 真实视频帧背景复杂
- P3M 图像: 高分辨率肖像, 背景相对简单

**已尝试的微调方案**:
1. 冻结 encoder + 3 epochs (lr=1e-4) → HM SAD=403 (无变化), P3M SAD=21.7 (退化)
2. 全量训练 + 3 epochs (lr=1e-4, size=384) → HM SAD=404 (无变化), P3M SAD=4.02
3. 全量训练 + 2000 HM 样本 + 2 epochs (lr=2e-4, size=384) → HM SAD=410 (略恶化), P3M SAD=5.36

**结论**: BiRefNet 架构在当前训练条件下无法适配 HM-1k 域。训练损失全程不降 (0.11→0.11), 说明模型已处于局部最优, 无法通过梯度下降逃离。已恢复原始权重。

**后续建议**:
1. 替换抠图后端: 使用 MODNet 或 RVM 等对视频域更友好的模型, 或用 DetectHumanMatting 做人体区域预分割 + BiRefNet 精修的级联方案
2. 增加训练分辨率: 从 384 提升到 1024 (与推理一致), 但需更大显存
3. 更长训练: 10+ epochs, 但基于当前 loss 不降的趋势, 效果存疑
4. 混合精度 + 混合分辨率: 训练时随机采样不同分辨率, 增强模型多尺度能力

### 5.2 SFT 数据增量训练

SFT 数据已重新生成 (326 条), 包含新增的:
- 8 条 abstain 样本 (覆盖 M4/M5 失败模式)
- 5 条 greenscreen 保留实物样本 (覆盖 G3/G4)
- abstain 格式统一为 `{"intent":"abstain","nodes":[],"outputs":[]}`

用新 SFT 数据微调 Planner LLM, 目标文本理解 >95%。
